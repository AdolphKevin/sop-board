# 数据库接口测试

来源及同步方法见 [SOURCE.md](../SOURCE.md)。把业务 SOP 保留为产品仓库中的接口测试，用真实后端入口与生产同类数据库核对确定结果。

## 先明确契约

编辑前从场景原文写明入口、登录身份与租户、应选记录编号、响应原因、应增改及应保持不变的行、计数、消息、审计与状态转换，以及负向分支和读后操作前的最终复核。核对确切值，不以“无错误”、非空响应或大致数量替代。

## 沿用仓库设施

1. 使用已有 API、gRPC 或服务数据库测试设施，调用真实后端入口，经过实际中间件、鉴权与业务层；直接 SQL 或存储层方法不能替代入口。
2. 使用生产同类数据库引擎、兼容字段类型与约束、真实迁移，在临时数据库或模式建立隔离的确定性数据。
3. 精确断言响应内容、原因、选中对象、数据增改与禁止写入。
4. 按已确认业务覆盖成功、较新但不合条件、没有匹配、租户/客户/资源不符、已处理与可重试状态，以及有先读后写间隔时的最终状态复核。业务不适用的分支说明依据，不能为凑覆盖虚构预期。
5. 边界外第三方依赖可以替代并列为未覆盖；目标入口及数据库路径使用真实实现。测试文件留在仓库，只清理本次获授权的临时数据与设施。

## PostgreSQL 运行器

仓库未提供真实测试数据库且生产使用 PostgreSQL 时，可使用随附脚本（`<技能目录>` 是当前技能实际路径）：

```sh
bash <技能目录>/scripts/run_postgres_test.sh \
  go test ./internal/service -run '^TestTargetSOPPostgres$' -count=1 -v

SOP_DB_ENV=DB_DSN bash <技能目录>/scripts/run_postgres_test.sh \
  go test ./... -run '^TestTargetSOPPostgres$' -count=1 -v
```

脚本优先使用 `SOP_DB_ENV` 指定的变量（默认 `TEST_POSTGRES_DSN`）；已设置时直接运行命令。未设置时启动隔离的 `postgres:16-alpine` 容器，导出 `TEST_POSTGRES_DSN`、`DATABASE_URL` 和指定变量，结束后删除容器。`SOP_POSTGRES_IMAGE` 可选生产兼容版本。已有连接须先核对确为获授权的测试库。凭据只经环境变量传递，运行输出须脱敏。

生产不是 PostgreSQL 时沿用项目已有对应引擎运行器；缺运行器则在产品测试设施中补充可复用的启动方法，不能用 PostgreSQL 或 SQLite 冒充生产引擎。

## 失败与完成

失败保留原始证据，从字段映射、查询构造、业务选择、响应转换、持久化找最早偏差。产品实现不符时保留失败用例、停止扩写并报告，由调用方决定修复；本技能保持产品代码不变。

本机通过须满足：真实入口和数据库实际执行，精确响应与数据断言成立，相关负向和禁止写入分支被覆盖；声明的每个测试在执行清单中且通过。跳过、数据库不可用、零用例或只有编译成功均记“未运行”。记录本次临时数据和容器清理结果。再按主技能核对检出能力，写 [regression.json](report.md) 并登记关联，交回命令、逐测试结果和原始输出位置。
