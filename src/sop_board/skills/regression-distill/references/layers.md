# 按业务结果选择测试层

先把原文中的每条预期分解为可观察断言，保留来源。按下表从低成本层选择，不能用低层通过推断未经过的鉴权、装配、通知或页面行为。

| 层级（报告值） | 选择依据 | 写法与边界 |
| --- | --- | --- |
| 单元 `unit` | 纯规则、计算、状态转换不依赖服务装配 | 使用既有测试框架，按已确认输入输出核对精确值与边界。外部调用和持久化行为另列未覆盖。 |
| 接口与数据库 `api` | 中间件、鉴权、业务选择与数据库共同产生结果 | 调用真实 HTTP、gRPC 或服务入口，使用生产同类数据库、真实迁移和确定性数据；精确核对响应、选中记录及增改与不变数据。执行前读 [数据库接口测试](backend-db.md)。 |
| 组件 `component` | 前端交互可在现有组件设施中观察 | 以用户操作驱动组件，核对可见状态及发送的业务请求；替代的服务与未经过的浏览器装配列为真实入口范围。 |
| 浏览器 `browser` | 业务保证必须穿过真实浏览器与服务 | 以场景独立通过时的 Playwright spec 为起点，放进产品仓库受版本管理的目录；命令声明 `browser: <身份>`，由看板提供浏览器与环境。改写断言须写账本，保真检查以 git HEAD 为基线。 |

一个测试可覆盖多条预期；同一断言不在多层重复覆盖。某条预期没有任何一层能完整观察时，这个场景不写进守护，继续靠真实入口复核。守护通过只用于产品变化后的复核，不替代首次独立验收、场景内容变化后的执行或缺陷复验。
