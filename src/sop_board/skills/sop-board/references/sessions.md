# 会话身份与独立执行

## 身份

优先使用工具的会话元数据、启动回执或结构化输出：

- Codex：优先读取当前子代理或子进程环境中的 `CODEX_THREAD_ID`；也可用 `codex exec --json` 事件流中 `thread.started` 的 `thread_id`。能取得原生编号时使用它，不改用替代标签；协调会话不能把自己的编号填给执行会话。独立交接用新的 `codex exec` 进程，不用 Codex 原生协作工具（spawn_agent、followup_task、send_message）：它们的消息以密文记录，无法核对。
- Claude Code：子代理工具返回的标识，或 `--output-format json` 结果中的 `session_id`。
- 取不到时，为该会话创建一次“工具名-日期时间-用途”的稳定标签，明确记为替代标签；同一会话后续执行、重试与登记复用它，不编造原生编号。

把标识和它的来源保存在本轮仓库外材料中。执行者身份必须是实际执行场景、写出结果并提交的那个会话：没有真正派出子代理或新会话时，不得使用为它预留的标签，由当前会话执行就登记当前会话并如实标为自检。prepare 的 --session 是执行者身份；execute submit 的 --implementer 是实际实现者。当前会话同时实现与执行时，两者使用同一身份。业务答复人、上传人和确认人使用使用者提供的姓名，不填写会话标识。

会话需要产品目录及工作区数据目录的相应写权限。Codex 启动时用 `--add-dir <数据目录>` 授予任务材料和登记所需权限；Claude Code 用 `/add-dir <数据目录>`。修复还需能写 prepare 列出的产品仓库，普通执行只在任务目录留证。缺少写权限时先由使用者按客户端方式授予，不绕过沙箱或改写其他数据目录。

## 独立交接

默认分两段创建未参与实现、且不继承上下文的新会话：第一段只要求它回报原生编号并等待，不含任何任务内容（Codex 用新的 `codex exec --json` 进程，读 thread.started 的 thread_id；Claude Code 用不继承上下文的子代理，标识以子代理工具返回的为准，不由子代理自报；或使用者新开的窗口）；用该编号 prepare，把交接全文写进任务目录的 handoff-<序号>.md（只在本机可见，不含凭据，再次交接另存新序号）；第二段把该文件全文作为同一会话的下一条输入（Codex 用 `codex exec resume <thread_id>`，并重复第一段的沙箱、`--add-dir`、`-C`、`--json` 与网络授权，第一段进程退出只表示会话可续接；Claude Code 向同一子代理续发，不能续发时改用 `claude -p --output-format json` 取得 session_id 后 `--resume`）。工具暂不能提前返回原生编号时，先为该执行会话建立稳定替代标签并告知其复用，不把该标签说成原生编号。

交接只包含：

1. prepare 返回的任务目录；清单、指纹、场景和输出约定从目录读取。
2. 项目验证技能与它引用的真实验证手册位置。
3. 入口环境说明与本任务授权记录的位置；凭据沿用环境变量引用，不放入交接文字或证据。

交接给独立会话时，任务目录除执行输出外以 prepare 生成的内容为准：协调者只追加 handoff-<序号>.md，不向任务目录写入其他材料（如自拟的需求说明或补充场景），交接也不引用上述三项之外的文件。使用者要求当前会话执行时，当前会话照常写结果与证据。需要使用者答复范围时（如“这批”指哪组场景），非交互客户端（如单轮 `codex exec`）先停止并等待下一轮输入，不自行假设范围。

交接须可核对：除客户端自动注入的说明外，协调者给执行会话的交接输入与 handoff-<序号>.md 全文一致，之后每条输入都有明文记录且不含实现推断；把会话记录位置与 handoff 文件摘要记入仓库外材料；客户端自动注入的记忆可能带有实现推断，在材料中注明。Codex 协调会话从沙箱内启动 `codex exec` 时需要网络授权与 `--add-dir <数据目录>`，Web 场景需要允许启动浏览器的沙箱。

不传实现者的推断、预设结论或“应该会通过”的判断。交接后直到执行完成，协调会话也不向执行会话补充实现推断或预设结论。执行者按提示词逐条操作并留证，由执行者或协调者用同一任务 submit。使用者要求当前会话执行时保持当前身份并登记自检；换一个标签不能制造独立性。

## 任务冲突与处理

先报告 status 中的待处理事项。task list/show 查看任务；使用者决定取消时用 task cancel。同批次同类任务或实际占用、恢复环境的任务才构成阻挡；其他仅排队或等待的看板任务不阻挡本次准备。同类排队任务经使用者同意后可用 prepare 的 --replace-queued；已中断、已放弃或已作废的任务保留历史，重新准备新任务，不接管或复活。已有明确授权沿用。

会话准备与提交直接访问本机数据，看板可以不运行。准备后的任务由会话持有；结束或取消前，看板不会替它启动模型。执行入口、执行者、实现者与独立性属于验收记录；任务目录、任务会话信息与代理附件只在本机查看。
