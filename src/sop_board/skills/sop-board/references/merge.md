# 会话合并

先完成 status 检查，按 [sessions.md](sessions.md) 记录会话标识。准备与提交使用同一工作区、数据目录和任务编号。

1. 取得测试同事的用例文件，并在本次上传请求中询问、确认上传人姓名；当次已明确指定上传人的，直接使用，不从此前自我介绍、其他角色或旧上传记录取名。运行 `sop-board cases upload <工作区> <批次> <文件> --uploaded-by <姓名> --session <标识>`。该上传触发的合并由会话认领。
2. 运行 `sop-board merge prepare <工作区> <批次> --session <标识>`，读取返回的提示词与任务材料，按契约写输出，再运行 `sop-board merge submit <工作区> --task <编号>`。已有未结束的本会话任务可继续准备；不要为同一轮另建会话。
3. 有缺口时，按 D66 业务场景格式逐项呈报：标题、场景、目前的写法、缺什么、请确认、涉及用例；保留返回的问题和依据，不替使用者补答，并请使用者答复时一并写明答复人姓名。收到针对当前批次和缺口的原话及姓名后运行 `sop-board merge reply <工作区> <批次> --gap <任务:缺口|none> --text <原文> --author <姓名> --session <标识>`；通用说明用 none，也只用于使用者针对的当前批次。再 prepare 下一轮。回复会以“会话”来源显示，是否采纳按任务提示词判断。
4. 只有使用者明确决定本批不纳入并给出理由，才运行 `merge exclude <工作区> <批次> --gap <任务:缺口> --author <姓名> --reason <理由>`；重新纳入用 `merge include <工作区> <批次> --case <用例编号> --author <姓名> --reason <理由>`。继续由本会话处理时加同一 `--session`。
5. 交回合并状态、已落地范围、仍待补充范围和用例更新。没有真实执行证据时，只报告场景已生成，不报告业务通过。

“你看着办”不是业务答复或排除决定；请追问。姓名必须来自使用者，不能用会话标识代填。未传 --session 的答复、确认或排除操作保留看板的后续调度；需要接续其排队任务时，先呈报编号，使用者同意后用 --replace-queued。运行中的任务不接管。不要直接改写看板数据库或自行生成场景文件替代 submit。

对话中已有的业务答复只属于它当时针对的批次与缺口。即使另一个批次的用词相似，也不得挪用旧答复或认为已经确认；向使用者呈报新问题并取得针对本次范围的答复。

## 按条增改与增量判断

只增改几条用例时，直接修改仓库内的用例文件，再运行 `sop-board cases put <工作区> <批次> --from <该文件> --case <编号> --case <编号> --by <姓名> --reason <使用者原话> --session <标识>`，只登记这次选定的条目。需要看板当前内容（含澄清改写）时，先用 `sop-board cases export <工作区> <批次> --case <编号> --out <新文件>` 导出，修改后 put；也可写只有 test_cases 的片段，文件头由看板继承。

新增或改写的步骤与预期由会话起草时，先逐条呈报给使用者确认，不把当前实现的行为直接写成预期；收到确认与姓名后再 put。用例文件在产品仓库内且计入产品快照时，修改它会使已有通过进入影响判定；可提示使用者在工作区 config.yaml 的 `snapshot_exclude` 中声明用例目录，由使用者决定。

`--reason` 保留使用者给出的原话或决定依据。姓名沿用入口技能的规则：使用者当次给出的姓名优先，否则只用默认业务确认人，都没有时先取得姓名，不能用会话标识代填。输出列出新增、改写、未变化及被替换来源；覆盖澄清版本时先向使用者说明，下一轮仍须核对已采纳答复。全部未变化时不登记记录。按条上传不记录原文件路径，不能写回；仓库文件由会话直接编辑后按编号登记。

prepare 返回 `mode=增量` 时，读取 delta.json，只须在 cases 给出 changed_cases 的全部判断。变化波及沿用判断时（如流程变成细节，原先并入它的条目也受影响），把这些条目的新判断一并给出，明确输出的条目会完整替换沿用值。缺口、节点及场景去向按任务增量说明沿用，补齐后仍执行全量核对。拒收后补上受影响条目，在同一任务重交。

需要整批重新判断时运行 `sop-board merge prepare <工作区> <批次> --session <同一标识> --full`。尚未落地的本会话任务保持编号，按最新输入重新准备为全量，归档已有失败输出并撤下 delta.json；没有当前任务时新建全量任务。全量输出覆盖全部用例与节点。交回时说明实际模式、变化判断数、沿用数及仍待补充范围。

## 缺口呈报模板

每个缺口单独按下面六项完整呈报，保留问题编号和业务依据。逐项复制模板填写，不改成表格或一行摘要；一个“请确认”只问一个业务决定。已知口径与来源可写入“目前的写法”，选项放在“请确认”中但不能当作已确认答案。

```markdown
### 标题：<缺口编号> <一句话标题>

**场景**
<谁在什么前置状态下，从哪里做什么；沿用用例的对象和数值>

**目前的写法**
<用例当前原文、已知口径及来源>

**缺什么**
<还缺哪一项业务依据或操作能力>

**请确认**
<只问一件事，等待使用者针对本批次本缺口答复>

**涉及用例**
<用例编号与标题；有多个时逐条列出>
```
