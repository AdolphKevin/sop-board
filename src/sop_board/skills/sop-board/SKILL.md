# Flow Board 会话入口

**等待答复：**需要使用者答复、选择或确认时，完整呈报后结束本轮回复，等待下一轮明确输入；本轮不再运行登记、上传、合并、生成或提交命令。`codex exec` 等单轮客户端同样在此结束。已有明确答复和授权时，按其范围继续。

1. 先在产品仓库运行 `sop-board status --json`。工作区未登记时停止，按 `sop-board guide` 引导使用者运行 `sop-board init`。已登记但数据目录权限不足时，按 [sessions.md](references/sessions.md) 授予权限，不另建数据目录。有待处理事项时，先报告种类、原因、链接与可用的续接方式，询问是否先处理；本任务已有明确的处理顺序时沿用，不重复询问。
2. 按使用者要完成的阶段读取一份参考，再执行其中的步骤：

| 使用者要做的事 | 读取材料 |
| --- | --- |
| 根据 PRD、需求、评审记录或技术方案写业务 SOP | [编写业务 SOP](references/author-sop.md) |
| 登记已有业务 SOP 原文，或生成、修订、确认草稿 | [草稿](references/draft.md) |
| 上传并合并用例、按条增改用例、回答合并缺口、本批不纳入或重新纳入 | [合并](references/merge.md) |
| 改场景的措辞、预期，或去掉某些场景 | [合并（按条增改 / 本批不纳入）](references/merge.md) |
| 梳理 Web 入口的交互地图，或处理执行者的地图反馈 | [梳理交互](references/atlas.md) |
| 执行或重新验证已存在的场景 | [执行](references/execute.md) |
| 分析并修复不通过的场景、登记修复后的独立复验 | [修复与独立复验](references/fix.md) |
| 记录问题台账、登记人的决定、导出或回写用例 | [问题台账与协同](references/ledger.md) |

3. 署名：答复、确认、上传、决定都用使用者给出的姓名，范围以一次请求为限。一次请求指使用者提出的一项操作，从提出到该操作登记完成，包括其中的差异呈报与确认往返；这次请求中给出的姓名可用于这次所需的全部署名。使用者提出新的请求时，之前请求中的姓名不沿用：新请求及其确认都没有给出姓名、又没有默认业务确认人时，先询问姓名，按等待答复规则结束本轮，不运行登记命令。`status` 显示了默认业务确认人时，各参考里要求“当次指定姓名”的步骤可省略姓名参数，命令以该姓名署名，呈报时说明；使用者当次给出其他姓名时以当次为准。不用会话标识或自我介绍代填。
4. prepare、submit 输出 `concurrency_notice` 时，向使用者说明同一工作区还有哪些会话的任务在进行，不替对方提交或取消。
5. 需要认领或交接时读取[会话身份与独立执行](references/sessions.md)。操作要求以 `prepare` 输出的提示词为准；按它读取项目验证技能和产品手册，不在会话侧重写校验规则。
6. 交付前：改动了已登记工作区的产品仓库，准备提交或宣布可以验收前，先运行 `sop-board status --json`，报告各批次的待执行与产品变化待判定数量。说明待判定场景下一轮逐条判定影响、受影响的须重跑，并根据实际改动估计大致范围与依据。报告前不宣布“可以进入验收”。

使用者在选择题中选定内容时，依据写成“选择：<选项原文>（问题：<问题原文>）”，保留选项与问题，不当作使用者原话。在新的请求中再次询问姓名、使用者给出与之前相同的姓名时，在同一条回复里写明命令：可以用 `sop-board confirmer <工作区> --set <姓名>` 把该姓名设为默认业务确认人，之后的署名可省略；是否设置由使用者决定，未得到同意不运行。不为触发这条提示在同一次请求里重复询问。
