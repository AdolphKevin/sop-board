# 任务内核、两个入口与证据有效性

各类任务通过 task_types 的 inputs、prepare、launch、consume、actions 约定接入 kernel；调度顺序、互斥、进度、恢复与归档保持单一实现，业务模块保留自己的资格与登记。任务按任务/尝试保存收据，重试归档不覆盖已有材料。数据库格式保持 5，旧表不加列，新增记录通过新表维护。

看板调度与开发会话共用输入校验和业务登记。session_tasks 保存认领，看板不调度或恢复接管这些任务；只能认领未认领的排队任务，结束任务重新准备。会话准备只受同批次同类任务及实际产品环境占用/恢复阻挡，不继承其他看板排队依赖。会话失败由使用者决定继续会话修复或本机交给看板，交接绑定具体失败结果。

Web 证据正文继续由入口 evidence 声明，web_evidence 仅控制录屏与 trace，缺省均开启；scope 按场景固定声明，模板与转换共用。产品摘要按仓库排除 snapshot_exclude 的明确路径，默认没有额外排除；场景、用例并集和配置仍各自核对。具体字段与配置示例维护在 docs/reference.md。

证据是否仍对应产品以内容摘要判断，提交本身不使通过记录失效。看板执行与沉淀仍等待产品提交；沉淀开始前内容相同可更新提交号，内容不匹配才待验证，等待不自动安排执行。运行中的固定输入仍要复核。会话执行允许未提交内容，并记录提交、改动清单、内容摘要及 dirty。

会话修复只改当前工作区产品代码，不写测试、不自行提交；复验必须由未参与修复的新会话完整执行。执行入口、执行者、实现者与独立性按真实关系记录，不能改标签制造独立验收。任务材料按类型白名单向内网投影，轮次业务身份不与任务级会话隐私混淆。

会话命令只在确实找不到登记工作区时附初始化指引，其他拒绝保留具体原因。编写业务 SOP 的公共规则随包提供并复制到任务目录，与 docs/sop-guide.md 对应规则同步；用普通 wheel 安装核对可读。原文答复时间与页面共用显示时区，原始答复记录不改写。最终正文与过程说明分开，确认信息由登记命令附加；业务提问和确认人询问不预设答案。看板未运行时报告已有位置，不为寻找链接额外运行命令。

命令、状态和字段的具体正文维护在 docs/reference.md；统一验收方法在 docs/verification.md。上述 guards 是业务场景索引，不是新增自动测试。
