# Flow Board 项目总览

Flow Board 流程验收看板。代理在工作区适配环境执行；测试同事上传用例、查看证据、复核结果和提交缺陷。看板展示轮次、通过率与进度，并导出验收结果。默认仅监听本机，可开放内网，不提供服务器部署。

行为以整体方案 D72～D83 及其明确保留的原方案与 v9 决策为准。[docs/standard.md](../docs/standard.md) 是业务验收标准的唯一正文，场景写法见 docs/sop-guide.md，四份记录模板在 docs/templates/；场景和结果字段由本仓校验器及 docs/reference.md 维护。验收以 docs/sop/ 经真实入口执行为准，开发中不写测试；本项目操作和留证见 docs/verification.md，历史知识数据保持读取兼容。

## 现行规则入口

- 任务内核、会话认领、D83 分流与内容摘要见 [两个入口与证据有效性](rules/task-entries-and-evidence.md)，具体命令和状态只在 docs/reference.md 维护。
- 看板修复、沉淀与自检使用 [工作树适配规则](rules/worktree-adapter.md)；会话修复在当前目录进行，不套用自动提交合入流程。
- 交验收前遵守 [沙箱与内网留证教训](lessons/2026-10-23-sandbox-and-lan-evidence.md)。编译、模拟消费、HTTP 页面和真实模型/浏览器/独立验收分别报告。
- K1～K6 的入口已实现，K7 整理文档；段末审核和冒烟不等于统一独立验收完成。统一范围在 docs/verification.md，验收 YAML 在实现会话只读；D82 外部技能退役在发布后另行处理。

## 项目事实与实施沿革

以下 K 段文字保留当时范围和未完成项，后续段及返工的明确修订优先；不能把早期“暂未提供”当作当前入口状态。

D31：普通写入免令牌，页面仅保存标记人；开发者操作仅接受实际回环连接，内网页面隐藏按钮。POST/PUT 检查同源与 JSON 类型，二进制证据上传仅免 JSON 类型要求。

工作区是页面、接口与数据归属单位，由名称加任意位置的仓库组成，用 sop-board init 登记（D37）。config.yaml 位于数据目录，是仓库和入口的唯一配置：repos 写绝对路径，scenarios 为 {repo, path}，skill 必填；仓库身份从 origin 规范化得到。旧数据目录不读取、不迁移。

适配环境：配置对应的自检全部通过且配置未变才启用执行与修复。环境按声明端口互斥，端口不重叠的工作区可同时运行，被占时每 10 秒重试（D48）；基线与修复目录共用端口；环境日志和自检详情仅本机显示，内网页面与接口不显示本机路径（D45）。看板执行等待产品提交，提交改变后先重启环境；开发会话入口允许未提交内容，按手册准备自己的环境。自检第 1 步核对各仓 Git 提交身份，第 3、4 步核对入口地址变量（D47、D52）。

验证：真实验证手册在产品仓库保存操作正文，工作区 entries 用简短说明引用手册章节；搭建代理在数据目录写项目验证技能，执行与复测先读技能，再读对应产品版本的手册及本任务授权记录（D60）。Web 入口缺省用随包 playwright-acceptance，其他入口不按 surface 缺省（D38）。技能变化使本轮作废，不使历史结果失效。产品变化后，会话写 impact.json，判定不受影响的必须沿用并写理由，看板核对判定与结果一致；rerun 全量不得沿用（D39、D46）。看板执行在同批次合并进行中时等待合并结束（D51）；会话入口按 D83 核对实际环境占用。

D33/I3 修订 3：先确认工作树建法和外部工具依赖；worktree/cleanup 适配替代旧准备命令，未声明才用默认 Git 建立/删除。路径须为对应仓库根目录，共用 Git common dir 且检出指定分支，自检与修复共用此核对。

跨仓修复：看板来源或明确交接的会话 Agent 失败在整个工作区没有排队、待提交、等待浏览器或运行中的执行后统一建修复任务；人工不通过在测试同事点“复核完成”后才纳入（D42）。缺 Git 身份时转开发者处理、不计尝试次数，重试从提交继续（D47）。各涉及仓库由适配建立工作树；只改产品，不写测试，配置或环境问题转开发者。整组预检通过才逐仓快进，基线前进须重新复测；失败或放弃保留现场，不还原、不强制移动分支。工作树文件不提供下载。

D35、I6：每条用例明确归为 flow/detail 并说明理由，仅 flow 生成场景；detail 的原预期带来源编号并入本次流程。配对绑定场景版本和用例内容，供页面与报告共用。本机指定单独成场景的选择持久保存，后续合并必须遵守。报告逐轮列出沿用数量与理由。模拟合并和报表记录须明确标记，不能替代真实 Codex 或独立验收。

Web 验收技能随 sop-board 发行，维护于 src/sop_board/skills/playwright-acceptance/。总览优先展示执行进度、Agent 通过率和复核进度；其他指标可展开，队列同时显示场景名称和编号，复核身份默认折叠，刷新保留展开状态。

D61–D65 第一段：regression-distill 随包发行，在开发会话把已确认、通过证据与当前内容一致的场景按成本分层沉淀；产品代码保持原样，测试改动留给调用方审核。skills install 将两项随包技能链接到 HOME 下的 Codex 与 Claude Code 目录，其他来源同名项保留并跳过。distill submit 只在本机核对整份报告的场景指纹、仓库身份及实际文件摘要，全部合格才登记 regression_links；同一测试提交后再次登记更新，过期按场景指纹计算，数据库格式仍为 5。页面与报告展示逐项覆盖和运行状态，内网隐藏测试命令与本机路径；人工不通过时提示关联测试待核查。关联不改变场景结论、轮次或交付判定，影响判断仍以完整改动及依赖关系为先；看板调度沉淀属于第二段。

D62 第二段：本机场景页可发起 distill 任务，整组核对确认与当前 Agent 通过证据。入队固定全部输入，未提交改动先待提交；提交后证据不匹配新产品时待验证，列出场景并等待实际执行或有效沿用通过后自动开始，保留入队快照；其余输入变化及开始与登记前变化则作废。复用 Worktrees 与 Environment.use_repair，任务间修复优先于执行、执行优先于沉淀；工作树从 SOP_BASE_COMMITS 指定提交建立。工作树身份和任务登记收据持久保存，登记按任务与尝试幂等；重启可恢复审核或中断，重试归档旧材料并复用现场。开发者自行提交后按提交核对全部产出摘要，再升级关联；清理需先展示改动并确认摘要，失败保留现场，分支不强删。内网任务采用字段白名单，沉淀附件全部拒绝；格式 5 通过新增表兼容，关联不写场景轮次。

D72、D73 的 K1a：任务状态、Codex 启动与事件解析、调度顺序和进度统一由 kernel.py 提供。修复优先于执行，执行优先于合并与草稿，最后是沉淀；同级按编号，排队位置直接使用这份顺序。同工作区的执行、修复、沉淀互斥，同批次的草稿、合并、执行互斥，沉淀也等待同批次草稿与合并结束。阻挡只更新原因，保留具体等待状态。session_tasks 记录会话认领，调度和看板重启恢复均不接管这些任务，页面保留原状态并显示处理会话；数据库格式仍为 5。草稿、合并、沉淀通过 task_types.py 的输入、准备、启动、消费和操作约定接入；执行与修复仅接入公共机制，工作树、尝试和业务登记继续沿用原实现。重启中断名单保留原行为（草稿、合并、执行的排队项也中断，沉淀的待提交、待验证保持），沉淀收据与修复合入恢复作为类型钩子执行。各类任务接口提供公共进度，事件摘要和续接命令只在本机返回；合并状态条沿用这些数据。依据为 docs/proposals/2026-10-22-integrated-rework.md 及 K1a 任务边界，统一任务页、会话命令和工作树机制统一仍属后续段。

任务读取与等待开销：调度每轮只查询一次参与调度的状态，列表只含任务编号、类型、工作区、批次与状态；业务准备按编号读取单个任务输入，本轮状态变化同步到内存列表。已结束但尚未退出的线程仍保留互斥，直到环境恢复完成。只读 HTTP 请求及直接批量读取共享一次排队位置计算，请求结束即释放，不能缓存到后续轮询。任务字段没有实际变化时不开始更新事务；执行已标记等待合并并要求合并后刷新时，不重复重写输入或删除快照。修复复验的浏览器等待原因由公共入口一次写入，避免两种等待文案反复覆盖。

K1b 接续上述 K1a：执行、修复及修复复验也实现 inputs、prepare、launch、consume、actions；复验借用修复任务的运行名额，仍在环境恢复后登记结果。输入比较使用 Inputs，等待间隔由类型声明并由内核管理。新归档统一放 attempts/序号，多次阶段留证进入其 checkpoints，旧 attempt-N、attempts/resume 与根 interruptions 保持读取兼容。fix_attempts 仍是业务记录；task_receipts 在同一任务与尝试内区分结果、修复输出、复验轮次等登记阶段，执行轮次及合并落地收据随业务事务保存，重启不重复登记。两张工作树表保持不变，由 TaskRepositories 统一读写和判断路径归属，不能归档或下载任务工作树。通用任务页为 /w/工作区/tasks/编号；合并页只查询、展示合并，沉淀和修复链接转到通用页。task_visibility.py 是每类任务内网字段和共享附件的唯一声明；会话、快照、文件清单、运行错误细节仅本机，内网保留明确挑选的业务结果，草稿版本同样不返回会话标识。原有响应及上传证据遮蔽继续保留。会话命令仍属后续阶段。

入口 credential_env 是变量名称数组；执行、修复、修复复测与沉淀只从启动进程取得声明的凭据，适配返回值不覆盖凭据。缺变量的涉及场景由看板记受阻，check 逐项报告设置状态；材料不保存取值，内网页面、接口与文本附件不显示名称。实际使用继续遵守任务开始时的账号授权。

产品展示名称统一为 Flow Board；安装包、命令、Python 模块、环境变量、数据目录及适配就绪标记沿用既有 sop-board 标识。

录屏证据在场景详情页通过原生 video controls 内联播放，保留下载链接；仅预加载元数据，不自动播放，视频证据 GET 支持单段 Range/206 与无效范围 416，方便拖动进度。

缺陷链接必填但原样保存，不校验、不补前缀；只有 http(s) 渲染为链接。仅 https://*.atlassian.net/browse/<单号> 识别为 Jira，凭据只读 JIRA_EMAIL、JIRA_API_TOKEN，只发往识别出的站点；Jira 站点与凭据由各项目使用方自行配置，搭建时代理只按变量名核对（D40、D41、D44）。

安装：pyproject.toml 的 uv cache-keys 让源码或提交变化时重新构建（D49）。搭建报告固定七节：已验证的事实、推断及依据、待回答的问题、工作树建立与清理方式、外部工具与外部依赖、验证技能摘要、Jira 读取（D50）。

D66、D67、D71（SOP-BOARD-13 T2）：合并缺口用业务场景语言表达，result.gaps 保存标题、场景、现状、缺少信息、单个问题、已知口径、至多三项选项及关联用例；result.held 保存暂缓用例、原因、缺口编号和原有场景。暂缓流程已有场景时保留整条原文、历史与原配对摘要；暂缓细节不阻止流程更新，只把它上一版已有的带编号预期、refs 与原配对保留下来，不给从未所属的流程添加预期。held.retention 区分 scenario/detail/none，统计和执行只排除整条暂缓场景，更新流程照常执行，暂缓细节的新内容不进入执行材料。settings 的 auto_execute 缺省开启，关闭只阻止自动执行入队；本机可切换，手动执行不受开关影响，重新开启不补发。数据库格式仍为 5；D68 的合并对话、回复状态与用例更新已由 K2 接续，补充方式见 docs/sop-guide.md，接口见 docs/reference.md。

K2（D68、D76）：合并对话记录人的原文、回复人、时间、缺口问题快照、状态、处理任务和来源；普通内网回复一律为“看板”，来源为“会话”的展示为 K4 保留。merge_followups 记录待发轮次，内核条件只在同批次无活动合并时发起一次，失败不会无限重试；运行中新增回复留到下一轮。输入包含全部澄清历史与排除决定，上传、重新合并和场景变化优先续接最近合并会话，回退归档失败材料并注明完整历史新开会话。输出先整体核对回复覆盖、已采纳引用与用例格式，再用更新后的用例组装；原输入未变化才把回复状态、澄清上传、场景版本及收据一并登记。重复消费不重复上传；全部暂缓也要核对输入。入口缺口的操作能力未改变时不得仅凭文字消除。“本批不纳入”保留用例与决定，排除快照判断和缺口计数，可逐条重新纳入。用例页和下载包含澄清更新，场景来源记录实际回复人；新的普通写入响应同样使用 K1b 任务字段白名单。数据库格式保持 5，仅新增表；K2 实现者自检不能代替真实模型、浏览器与独立验收。

K1b 返工 1：修复尝试的“待验证”表示修复输出与提交已经登记。复验中断后的重试直接进入同一次尝试的独立复验，先核对原配置、用例、场景、修复提交与目录，不再次修复或提交；不把这个阶段当作仍需续接修复的 ATTEMPT_RESUMABLE。未登记的旧复验目录保留，分配新的复验序号；修复会话中断仍按原路径继续。新建与续接统一读取输出模式，修复类型显式声明 schema。任务进度的最近活动可来自复验，但继续会话仅指向修复；本机复验记录单列会话编号，内网运行与成功状态使用对应业务说明。D79 的轮次执行者、实现者、提交者展示保持不变。

K2 返工 1：重新纳入的按钮文字按操作目标确定；澄清来源统一按 ref、version、confirmed_by 顺序写入。合并核对后，如场景数据与推断注释均未变化，沿用已有原文；完全相同时不替换场景文件、不登记新版本，但仍保存本轮有效回复和任务收据。推断注释变化不能被这种去重吞掉。新增澄清依据日期与页面、报告的不纳入日期共用 time_format 的显示时区，不截取 UTC 日期；不批量改写历史用例正文。缺口回复只能用于它保存的问题快照中的关联用例，通用说明的直接对应关系由提示词要求说明。单个问题、未知名词、直接影响范围和用例内部可验证性要求已收紧；真实模型语义效果仍须真实 Codex 复核。

K3（D62 入口二、D63、D64）：沉淀资格拒绝整条暂缓场景及保留旧细节预期的流程，并只从与当前用例内容相符的配对追溯确认；显式待确认标记不能由旧草稿确认覆盖。暂缓状态纳入固定输入，排队或登记前出现新暂缓则作废，旧任务缺少该字段按无暂缓兼容。开始前允许提交号更新，前提是产品内容摘要及其余固定输入不变，保留原入队快照并按新提交准备工作树；通过依据仍只比较内容摘要。内容不匹配时等待当前产品的通过证据，自动执行关闭时须由开发者手动发起验证。尚未开始、无工作树记录且没有运行线程的任务放弃后直接已放弃；有现场的仍按原清单确认和适配清理，失败保留。K1 调度与 K2 合并代码不变，原回归关联不写场景轮次；实现者模拟登记和清理边界不替代真实沉淀、真实工作树或独立验收。

K3 返工 1（审核方按 D22、D71 明确）：待验证的沉淀不自动安排执行，不受自动执行开关影响。任务页及场景页列出需通过的场景，本机“执行这些场景”使用现有 executions 入口传入明确编号；产品变化待判定项保留影响判断及有效沿用，已有其他排队范围时先处理原任务，不扩大此次指定范围。通过后沉淀自动开始。被中断尝试也保存实际会话身份，重启可从本次事件找回；页面身份与进度一致。正常停止时固定结束时间，重启和清理不覆盖，审核等待不计运行时长。工作树错误包装保留已有日志路径，避免重复。
