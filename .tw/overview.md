# sop-board 项目总览

SOP 场景验证协作看板。代理在工作区适配环境执行；测试同事上传用例、查看证据、复核结果和提交缺陷。看板展示轮次、通过率与进度，并导出 team-workflow 可登记的结果。默认仅监听本机，可开放内网，不提供服务器部署。

行为以 docs/designs/ 当前方案与 v9 决策为准。场景和结果字段与 team-workflow、sop-verify 同义，各仓独立实现。验收以 docs/sop/ 经真实入口执行为准，开发中不写测试；操作和留证见 docs/verification.md，.tw/config.json 保持原样。

D31：普通写入免令牌，页面仅保存标记人；开发者操作仅接受实际回环连接，内网页面隐藏按钮。POST/PUT 检查同源与 JSON 类型，二进制证据上传仅免 JSON 类型要求。

工作区是页面、接口与数据归属单位。config.yaml 位于数据目录，是仓库和入口的唯一配置；仓库身份从 origin 规范化得到。旧数据目录不读取、不迁移。

适配环境：配置对应的自检全部通过且配置未变才启用执行与修复。本机一套环境，基线与修复目录共用端口；环境日志和自检详情仅本机显示。未提交产品改动等待提交，提交改变后先重启环境。沿用必须保留通过状态、证据和理由。

D34：各涉及仓库在任务 repos/<别名> 建工作树；只改产品，不写测试，配置或环境问题转开发者。整组预检通过才逐仓快进，基线前进须重新复测；失败或放弃保留现场，不还原、不强制移动分支。工作树文件不提供下载。

D35、I6：每条用例明确归为 flow/detail 并说明理由，仅 flow 生成场景；detail 的原预期带来源编号并入本次流程。配对绑定场景版本和用例内容，供页面与报告共用。本机指定单独成场景的选择持久保存，后续合并必须遵守。报告逐轮列出沿用数量与理由。模拟合并和报表记录须明确标记，不能替代真实 Codex 或独立验收。
