# sop-board 项目总览

SOP 场景验证协作看板。代理在工作区适配环境执行；测试同事上传用例、查看证据、复核结果和提交缺陷。看板展示各轮通过率、复测率与进度，并导出 team-workflow 可登记的结果。

任何成员 clone 后用 uv 在本机启动，默认只监听本机，团队共用时由启动者开启内网访问。暂不提供服务器部署。

场景文件与结果文件的字段与 team-workflow、sop-verify 同义，三个仓库各自实现，不共享代码。接口、存储与统计口径以 `docs/designs/` 中当前需求的方案为准。

当前访问规则见 `docs/designs/SOP-BOARD-7.md` I1 与 `docs/proposals/2026-10-20-v9-workspace.md` D31：页面仅保存标记人，普通写入免令牌；开发者写操作只接受实际连接来自回环地址，非回环页面不生成开发者按钮。POST、PUT 校验同源与 JSON 类型，二进制证据上传仅免 JSON 类型要求。T2 使用数据目录的 `config.yaml` 声明工作区和仓库，已删除 `--writable-repo`。

验收以 `docs/sop/` 的场景经最终交付产物的真实入口执行为准。按 AdolphKevin 对 SOP-BOARD-7 T1 的第二次更正，删除仓库现有测试与仅供测试使用的依赖、配置和辅助脚本，开发中不写单元、接口与集成测试。命令、数据核对和留证方式见 `docs/verification.md`；本次保持 `.tw/config.json` 原样。

工作区是当前页面、接口和数据的归属单位，名称由目录名及必要的路径摘要确定。仓库身份从 origin 读取；入口只来自工作区配置，不读取仓库内的旧入口配置。旧数据目录拒绝读取，新数据使用 workspace.sqlite3。

适配、自检与环境生命周期见 v9 D33 和随包 guide.md。五步自检通过且配置未变后才启用执行与修复；本机只有一套环境，基线与修复目录共用端口。环境日志与自检详情仅本机展示。产品快照覆盖批次涉及仓库，未提交改动等待提交，提交号改变后先重启环境。沿用仍是通过结果，但必须有理由并单独计数。

跨仓修复见 D34、I5：涉及仓库的工作树位于任务 repos/<别名>，prepare 只处理这些目录；会话给出根因仓库，只改产品、不写测试，本机配置问题转开发者。整组预检通过才逐仓快进，基线前进先在修复目录合入并复测。失败或放弃保留现场，不还原或强制移动分支；合入后清理。结果按仓库记录，工作树文件不提供下载。模型不可用时仅验证明确标记的模拟阶段，不伪造独立复测通过记录。
