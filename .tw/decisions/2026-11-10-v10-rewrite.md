# v10 以会话 CLI、仓库场景文件与守护测试为核心整体重写

背景：v9 靠决定条目逐条打补丁扩张。实际使用中出现 7 个问题：自身场景冗余；看板难以按场景复测；不支持多 worktree；通过后不沉淀低成本测试；只能接管已打开的 Chrome；Playwright 崩溃；反复确认“确认人”。用户确认（2026-11-10）不修补，直接替换，不保留双轨与兼容代码。

决定（详见 docs/design.md）：

- Agent 工作只走会话 CLI 一条路径。看板的“AI 重跑”“沉淀”按钮只在本机可用，用同一技能启动无头会话。
- 场景 yaml 在产品仓库中，是唯一真相，看板不存版本，也不回写。结果按“检出 + 场景指纹 + 产品快照”登记。
- 新增检出（main 与 worktree）概念，按 git common dir 识别。环境、端口（`port_step` 偏移或租约）、浏览器与结果都按检出隔离。
- 独立通过的场景进入“待沉淀”；沉淀出的测试登记在产品仓库的 `regression.yaml`。产品变化后由 `sop-board retest` 直接运行这些测试，全部通过即“守护通过”；失败、缺失或过期时，才交 AI 走真实入口。
- 浏览器只由用户终端启动的看板守护进程启动：自带 Playwright 运行时与 Chrome for Testing，每个 检出×身份 一份持久 profile，执行者通过 CDP 连接。
- 操作者身份按机器设定一次，CLI 自动署名，会话不再询问确认人。
- 看板改为三栏场景工作台。内网只能查看、标注、答复、批注、上传。
- 本仓开发期间不写测试；现行场景集经独立验收后，再沉淀为 pytest。

## 备选
- 在 v9 上逐项修补：两条入口和任务内核仍在，每个问题都要再加规则与场景，维护成本继续上升，不采用。
- 环境改由执行会话按手册自行启动、删除 adapter：用户选择保留 adapter 脚本，由看板守护进程按检出启停。
- 守护测试由执行会话运行、看板只核对：仍需要 AI 参与，复核慢，不采用。
- 开发期间随代码写 pytest：用户选择先验收再沉淀。

## 后果
- 旧数据目录不读取、不迁移，cw2 需要重新 init。旧结果只能在旧目录和 Git 历史中查阅。
- `sop-board serve` 必须由用户在终端启动，CLI 涉及环境与浏览器的操作都依赖它。
- 守护测试一旦漏检（守护通过后，真实入口或人工复测发现失败），该守护失效，直到重新沉淀。

## 放弃过的做法
- 看板后台调度与会话认领两条入口，共用 25 种状态的任务内核（排队、互斥、认领、接管、替换排队）
  放弃原因：规则数量随场景组合增长，是维护困难与大量反向场景的主要来源
  重新考虑的条件：出现必须在无人值守时批量调度、且会话启动器无法满足的需求
  来源：tag v9-final 的 kernel.py、task_types.py、session.py；docs/design.md
  关键词：任务内核、看板调度、认领、task-owned、replace-queued、待同步、等待浏览器
- 看板保存场景版本并由合并回写场景文件，手改场景要走 scenario-edited/restore
  放弃原因：同一份场景有仓库与数据库两个真相，手改会被静默覆盖；多 worktree 下无法区分
  重新考虑的条件：场景不再由仓库管理
  来源：v9-final 的 service.py push、repositories.py Discovery；docs/proposals/2026-11-04-session-board-friction.md（v9-final）
  关键词：场景版本、合并回写、scenario-edited、merge restore、全量合并、增量合并
- 只通过 CDP 接管用户已打开的 Chrome，身份是用户手开的调试地址
  放弃原因：不能自带浏览器，Chrome for Testing 未安装，单一浏览器名额阻塞执行
  重新考虑的条件：无
  来源：v9-final 的 playwright-acceptance 模板 connection.mjs、identities.py
  关键词：接管 Chrome、DevToolsActivePort、PW_CHROME_USER_DATA、chrome://inspect
- 每次登记都要真人姓名，姓名只在一次请求内有效，默认确认人须用户另行同意
  放弃原因：会话在同一任务里反复询问署名，打断工作
  重新考虑的条件：多人共用同一台机器登记且需要区分签名
  来源：v9-final 的 skills/sop-board/SKILL.md 署名规则、session.py person
  关键词：确认人、署名、--by、--author、--confirmed-by、confirmer --set
- 本仓不写测试、只以场景验收，回归关联不改变结论
  放弃原因：确定性规则全部写成场景，产品一变就要整条重跑，731 条场景难以维护
  重新考虑的条件：无
  来源：v9 修订 2（2026-10-20）；docs/proposals/2026-11-09-current-scenario-set-and-guarded-regression.md（v9-final）
  关键词：不新增测试、关联不改变结论、regression_links、只认场景
- 每个需求新开一个场景文件，只增不并
  放弃原因：没有“产品现在应该怎样”的场景集，旧场景与过时写法一直在影响判定中被拉进来
  重新考虑的条件：无
  来源：v9-final 的 docs/sop/sop-board*.yaml
  关键词：sop-board-N.yaml、按需求拆文件、场景退役
- 问题台账、决定记录、执行计划与连续运行、只读巡检、Jira 联动
  放弃原因：用户确认（2026-11-10）删除；问题即失败场景加缺陷链接，决定写进仓库文档或场景来源
  重新考虑的条件：用户提出明确需求
  来源：docs/design.md 已定决策第 11 条
  关键词：issue、decision add、plans、连续运行、patrol、巡检、Jira
