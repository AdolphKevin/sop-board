# 一台机器一套环境，多个 Agent 轮流和并行使用

产品决定以 docs/design.md 已定决策 28 为准。背景：同一台机器上几个 Agent 在不同 worktree 并行开发同一产品，验收时互相挡住。看板一停就停掉全部环境、无头浏览器和它启动的会话；`port_step: 0` 时别的检出直接 `env-busy`、不排队；同一检出只能有一个 prepared 运行，且一次运行租下入口的全部身份；浏览器按 检出×身份 各一份 profile；结论按分支名归属，合并回 main 后不算数。

用户确认（2026-11-13）：一台机器多开环境是伪需求，大多数电脑的内存撑不起；要更多并行就加机器、加人（多机共享记录见已定决策 21）。决定是一套环境让多个 Agent 轮流用、并行用：

- `stop` 正常停止；`restart` 换守护进程，保留全部浏览器（含无头）、租约、启动的会话和 prepared 运行，环境由新进程重新拉起，受影响的运行记一条中断。会话输出改由随会话存活的转写进程遮蔽后写日志，遮蔽范围不变。
- `port_step: 0` 时环境由当前检出的 prepared 运行占住，空闲时自动换给等待的检出；`run prepare --wait` 在守护进程内存里按到达先后排队，按会话编号保留位置 60 秒；有别的检出在等时，占用的检出不能再开始新运行。
- 同一检出可以有多个 prepared 运行，`--identity` 分开身份，身份租约整机独占；`pending` 跳过别的运行里的场景；`env stop|start` 要求这套环境上只有这一个运行。
- 身份浏览器按身份一份（`browsers/<身份>/profile`），换检出时只清 HTTP 缓存；缺省端口 `9400 + 身份序号`。旧 profile 不迁移，用户确认（2026-11-13）升级时重新登录一次。
- 结论随合并带回：准备时快照干净、执行期间产品没变、各仓库提交已是本检出 HEAD 祖先的结论算本分支的，用共享运行记录里已有的快照判断，不改表结构。
- 本机库格式升到 8（用户确认，2026-11-13）：本机库与业务记录的格式号分开（本机 `LOCAL_VERSION` 8，业务记录 `VERSION` 7），共享库不受影响；`local_work` 的唯一索引只约束 distill，`browser_instances` 以身份为主键并记 `last_checkout`。旧本机库按 `project-format` 拒读，移走 `board.sqlite3` 后重建；没配共享库的项目连同业务记录一起重建。
- 实现要点：`gate.py` 在守护进程里排队与分配。`run prepare` 先在一个本机事务里登记运行并占住场景，再调 `/local/run/acquire`；分配后、运行目录写好之前的运行记在内存的 `granted` 里，算作占用环境。前面有冲突的等待者（别的检出等环境，或等同一身份）时不分配。不带 `--wait` 再来的会话放弃保留的位置。守护进程启动时清掉没写好运行目录、又已过两分钟的 prepared 运行。

## 备选

- 每个检出各起一套环境（Docker Compose 等现成方案）：cw2 梳理（2026-11-13）一套约 3.2 GB 加 Kafka 1.2 GB，16 GB 的机器已在大量使用 swap；主题名是代码常量、消费组写死，每套都要单独的 Kafka；开发配置在各仓库被 git 忽略、只从文件读，每套都要复制后再改；现有 Dockerfile 只给 CI 用。Docker 只解决端口，解决不了这些。
- 每套环境各用一个 Redis：定时任务的分布式锁（固定 key 的 SetNX）和雪花 ID 节点号都靠共享 Redis 协调，分开会让定时任务每套各跑一遍、ID 可能撞号。
- 槽位池、按身份转发流量的浏览器代理：服务于一台机器多套环境，随该方向一起不做。
- 环境跨看板重启保留：环境 adapter 的输出经守护进程管道转写，要保留就得另起转写进程并认回进程组；cw2 环境热缓存下 8～42 秒就能重新拉起，不值得。
- 沿用 main 检出下的旧 profile 目录、避免升级时重新登录：目录名里的检出名会误导，用户选择重新登录一次。
- 持久保存的排队：会把环境分给已经离开的会话；只记正在等的请求更简单。

## 后果

- 并行的上限是这套环境里的身份数；检出交替排队时会反复切换环境。要更多并行就加机器。
- `port_step` 保持现状，只适合演示项目这类轻量产品；真实产品一般设为 0。
- 看板重启时环境中断几十秒，执行者按提示词等环境就绪后重做期间失败的场景，不记失败或受阻。
- 要让验收结论随合并带回 main，验收前先提交；工作区不干净时取的证只按分支名归属。
- 多台机器共用同一批测试账号时的互相干扰仍未处理（已定决策 21 推迟）。
