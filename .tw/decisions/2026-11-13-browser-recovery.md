# 看板重启保留并认回有界面浏览器

产品决定以 docs/design.md 已定决策 26 为准。正常停止保留有界面窗口、输出保留清单；无头浏览器与环境仍停止。启动时只按本项目 profile 的进程锁核实本机进程、运行时可执行文件、完整 profile 参数、监听进程与调试应答，认回有界面窗口；核实属于本项目的无头进程结束，核对不通过的有界面窗口保留并登记未认回，进程已消失时忽略。

不依赖旧实例记录。检出尚未登记时按 profile 所在检出名暂存实例，登记后绑定本机记录；实际端口来自进程参数。非子进程以启动时间与命令行监视，未知退出码写“进程已退出”，沿用租约与崩溃规则。环境孤儿进程组清理不变。

## 实现边界

- 启动时按命令行目录前缀结束全部遗留浏览器：会丢失仍有效的窗口内登录与人机验证。
- 单凭调试端口应答认回：端口可能被其他进程占用，必须核对监听进程。

用户确认的返工要求（2026-11-13）：有界面窗口的端口核对在后台重试最多 15 秒，各次尝试之间等待最多 0.2 秒，同身份的租约与打开请求等结果，不另起进程。lsof 没有监听者信息时，使用 chrome.log 最后一次 DevTools 监听行与调试应答的端口、浏览器标识核对；明确给出其他进程时不请求该端口。无头遗留进程仍立即清理。核对线程自身异常时保留窗口并让请求报错，避免把核对故障变成重复启动。

认回后的日常监视每秒检查存活，最多每五秒完整核对一次启动时间与命令行；发任何结束信号前都重新核对。自己启动的 Popen 子进程仍每 0.2 秒监视，退出码与信号获取方式不变。

审核方按使用者确认的设计修订（2026-11-13）：十五秒核对不通过的有界面窗口不再自动结束。实例保留进程号、原端口与原因，status 显示 unrecovered；租约与打开请求返回 browser-unrecovered，并提示恢复后重试或用 browser close 结束。下一次请求重新核对，通过后沿用原进程；未认回状态不记崩溃。状态由守护进程内实例维护，数据库中的 starting 表示尚未就绪，status 依据实例显示未认回及原因；重启时仍按 profile 重新核对，不依赖旧状态。close 可以结束未认回窗口，正常停止看板保留它。

认回时 started_at 使用进程实际启动时间；取不到退出信号时，崩溃记录保持空信号，提交说明写“已退出（取不到退出信号）”。

sop-board restart 交接（已定决策 28，2026-11-13）：旧守护进程把运行中的浏览器（含无头的）与租约持有者写进项目数据目录的 restart.json，退出时不结束它们；新守护进程由旧进程启动（继承它的环境变量），按 restart.json 里的 profile 认回，无头的也认回。交接下来的租约在核对开始前就写回，核对期间别的运行拿不走；交接下来的无头浏览器核对不通过就结束它，租约留给原持有者，下次取得时重新启动。没有交接记录的启动照旧：只认回有界面窗口、释放旧租约、结束遗留的无头浏览器。
