## 目标与非目标

目标：修正下列七处行为，并补齐对应场景。

非目标：
- 修复会话内部的分析方法；
- 自托管 Jira；
- 跨机器的环境协调；
- 对共享基础设施（数据库、缓存、消息队列）做隔离。共享基础设施仍只在搭建报告中写明。

## D46 已证明不受影响的场景必须沿用

- 执行提示（`prompts/execute.md`）中，对 `pending.json` 里 reason 为 `source-changed` 的场景，规则从“只有……才可沿用”改为：会话按改动范围判定影响，**判定不受影响的必须沿用**，写成 `status: pass`、`note: 沿用：<改动范围、依赖关系和不受影响的理由>`，不再实际执行；判定受影响或无法证明不受影响的，必须重跑。
- 会话须在任务目录写 `impact.json`，逐条列出 `scenario`、`affected`（true/false）、`reason`。看板读取结果时核对两者一致：
  - `affected: false` 的场景必须是沿用行；
  - `affected: true` 的场景必须是实际执行行。
  
  不一致时本轮不合格，错误写明场景编号。
- 其他 reason（`new`、`changed`、`failed`、`rerun`）规则不变。

## D47 缺 Git 身份交给开发者，不计入重试

- **自检第 1 步**：核对每个已声明仓库的 `git config user.name` 和 `user.email` 都非空。任一为空时第 1 步失败，消息写明仓库别名和缺少的项，并提示设置方法：仓库级 `git -C <仓库> config user.name …`，或全局设置。
- **修复提交前**：再核对一次，规则相同。缺失时不进入提交，也不计入尝试次数。任务转为“待开发者处理”，原因写明仓库和缺少的项。这种状态下允许点“重试”，从提交步骤继续，修复工作树和已有改动都保留。
- 修复会话判为 `environment` 类别的问题，照旧转“待开发者处理”，不计入三次失败上限（保持现有规则），并在报告中写明。

## D48 环境锁改为按端口互斥

- 删除用户级的整机环境锁 `/tmp/sop-board-environment-<uid>.lock`。
- 启动环境前，按 `adapter.ports` 排序后，逐个获取端口锁 `/tmp/sop-board-port-<uid>-<端口>.lock`。锁内容写入持有者的工作区名称与数据目录。只要有一个端口拿不到，就释放已拿到的锁，环境不启动，提示“端口 <端口> 正由工作区 <名称> 的环境使用”。
- 声明端口互不重叠的工作区，可以同时运行各自的环境。
- 环境因端口锁未启动时，看板每 10 秒重试一次，拿到锁后自动启动基线环境，不再需要手动重启。页面环境栏显示“等待端口 <端口>（工作区 <名称>）”。
- 搭建指引要求：`adapter.ports` 写入环境中**所有服务监听的端口**，包括服务之间互相调用的端口；共享的外部基础设施端口（如开发库、缓存）不写入，但要在搭建报告“外部依赖”一节写明。

## D49 安装时按源码变化重新构建

在 `pyproject.toml` 增加：

```toml
[tool.uv]
cache-keys = [{ file = "pyproject.toml" }, { file = "src/**/*" }, { git = { commit = true } }]
```

这样，从本地检出运行 `uv tool install --force <检出>` 时，提交变化或 `src/` 下的文件变化都会触发重新构建。README 与搭建指引中的安装命令保持不变。

## D50 搭建报告固定模板

搭建指引“报告并启动”一步，给出必须使用的报告模板。报告写入数据目录的 `setup-report.md`，并在会话最终回复中给出同样内容。以下二级标题必须按顺序出现；某一节没有内容时写“无”：

1. 已验证的事实（附命令或日志位置）
2. 推断及依据
3. 待回答的问题
4. 工作树建立与清理方式
5. 外部工具与外部依赖（来源：仓库内、团队共用或仅本机；共享基础设施）
6. 验证技能摘要
7. Jira 读取

## D51 执行等待同批次合并结束

- 同一批次有排队中或运行中的合并任务时，该批次的执行任务进入“等待合并”状态，不启动会话；合并结束后，按最新场景版本冻结快照再开始。
- 合并失败或作废时，执行按当前已有的场景版本开始。
- 页面在执行任务旁显示“等待合并 #<编号>”。

## D52 自检核对入口地址变量

- 自检第 3 步（基线环境）就绪后，逐个核对声明了 `address_env` 的入口：该变量必须出现在看板进程环境中，或出现在适配返回的环境中，且非空。缺失时第 3 步失败，消息写明入口名和变量名。
- 第 4 步（临时工作树环境）对返回的环境做同样的核对。
