# 场景验收操作手册：sop-board

验收以 `docs/sop/` 的场景经真实入口执行为准。依据 AdolphKevin 对 SOP-BOARD-7 T1 的第二次更正，开发中不产出单元、接口与集成测试；现有测试、pytest 依赖及 Node 页面模型已删除。

预期结果来自已确认的 SOP 与方案。v9 当前依据为 `docs/sop/sop-board-7.yaml`、`docs/designs/SOP-BOARD-7.md` 和 `docs/proposals/2026-10-20-v9-workspace.md`。按本次交付范围选择场景，尚未交付的工作区、适配和跨仓能力单独记录，不将实现者自检记为独立验收。

## 真实入口与观察位置

| 入口 | 执行方式 | 核对结果 |
| --- | --- | --- |
| 命令行 | 在交付目录运行 `uv sync` 和 `uv run sop-board` | 标准输出、错误输出、退出码、实际监听地址、数据目录 |
| HTTP | 用 curl 请求实际启动的服务，分别使用本机与内网地址 | 状态码、响应正文、SQLite 数据、证据文件 |
| 页面 | 用真实浏览器按场景填写、点击和查看 | 页面变化、请求记录、截图及对应数据；仅取 HTML 不等于完整浏览器操作 |
| 导出 | 从实际看板导出一轮结果，再通过目标工具的真实入口登记 | 导出原文、证据字节、目标工具的登记结果 |

看板使用 Python 3.10 以上、uv、PyYAML 和 SQLite（WAL）。数据由 `--data` 指定，验收每轮使用新的临时目录与空闲端口。页面无登录，只保存自声明的标记人。普通写入无需令牌，开发者写操作只接受实际连接来自回环地址；POST、PUT 校验同源，JSON 接口要求 JSON 类型。

## 本段免令牌与访问范围验收

1. 运行 `uv sync`。不设置看板令牌，执行 `uv run sop-board --data <临时目录> --port <空闲端口>`，确认输出本机地址并可访问。
2. 用 `curl --noproxy '*'` 向 `127.0.0.1` 推送合格场景文件或登记人工标记，不发送认证头，核对成功响应以及 SQLite 中的版本或轮次。
3. 用 `--host 0.0.0.0` 启动隔离看板。通过 `network.local_ipv4_addresses()` 取得本机非回环 IPv4；以该地址请求开发者接口，例如 `POST …/executions`，核对 403 `local-only`，任务数据未变。
4. 从 `127.0.0.1` 发写入请求并带 `Origin: http://evil.example`，核对 403 `cross-origin`；将 JSON 接口的 `Content-Type` 设为 `text/plain`，核对 415 `json-required`。被拒绝请求不得留下业务数据。
5. 用内网地址与本机地址分别取得同一批次总览 HTML。内网 HTML 不含开发者按钮，本机 HTML 含暂停/恢复等可用按钮；授权仓库的本机批次页还应显示执行与回归检查按钮。本段授权仍使用 `--writable-repo`，不依赖令牌。
6. 需要验证二进制上传时，使用 `POST /api/v1/evidence`，核对返回的摘要、大小和下载原始字节。该接口只豁免 JSON 类型要求，仍核对 Origin。

除二进制证据上传外，写入命令应带 `Content-Type: application/json`，可带 `charset=utf-8`。不带 Origin 的命令行请求正常处理。地址限制以实际连接对端为准，转发头不能代替它。

本机反向代理和端口转发视为开发者本人的操作。内网同事访问时使用实际内网地址，不使用 `0.0.0.0` 作为浏览器地址。

## 数据、证据与清理

- 使用隔离数据和演示项目，不操作真实项目或账号。真实账号的交互式登录由用户完成；凭证不进入请求记录或报告。
- 留存执行版本、未提交改动、时间、执行者、完整命令、服务输出、请求与响应、操作前后的 SQLite 查询与输出。页面操作补截图；导出与上传保留原始文件和摘要。
- 负向场景同时核对没有新增记录、任务、文件或其他禁止的副作用。发生失败时先保存证据，再停止服务和清理本轮资源；不能清理时记录具体进程、端口与目录。
- 首次业务验收由未参与实现的执行者经真实入口完成并留证。实现者操作记为交付准备；真实浏览器、跨机访问、真实 Jira 等没有实际执行的部分明确写为未完成。
- `.tw/config.json` 按本次要求保持原样，其中既有 pytest 检查声明不作为当前验收入口；删除测试后该命令无法执行，配置衔接另行处理。
