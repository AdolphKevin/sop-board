## 入口与运行方式

### 入口：unit（集成）

- 覆盖的业务保证：G1、G2
- 起点、终点与经过的真实关键环节：测试在子进程启动 `sop-board`，经 HTTP 请求接口与页面，终点是响应、页面文本、SQLite 行与证据文件
- 依赖启动、版本与就绪核对：测试轮询首页直至返回 200 或超时失败；`uv --version`、`python3 --version` 记入执行记录
- 隔离数据：每个测试新的临时数据目录与空闲端口；重复与并发运行互不影响
- 本机命令：`uv run --frozen pytest -q -p no:cacheprovider tests`
- CI 任务、参数来源与结果位置：未建设
- 只运行指定场景的方法：追加 `-k <用例名>`
- 失败证据：pytest 输出、JUnit 报告与失败测试的服务日志，由 `tw team run` 保存在 `.tw/local/` 的运行目录
- 清理：测试结束时停止服务并删除临时目录；停止失败时测试报错并给出进程号
- 替代依赖与未覆盖范围：无替代依赖；跨机浏览器访问与 tw 登记由场景验收覆盖
- `.tw/config.json` 检查编号与覆盖层次：`unit`，`interface`，`stateless`
- 入口验证证据：待建设
- 维护人：AdolphKevin

### 入口：场景验收 cli、api 与 web

- `cli`：在检出目录启动与停止看板，记录命令、输出、退出码、监听地址与数据目录
- `api`：用 curl 调用接口，写入请求带令牌，记录请求与响应原文（令牌脱敏）与 SQLite 查询
- `web`：用浏览器操作页面，跨机访问用内网另一台机器，记录截图、页面文本、请求记录与 SQLite 查询
- 结果按 tw 结果契约写入仓库外的目录，用 `tw team scenarios submit` 登记
